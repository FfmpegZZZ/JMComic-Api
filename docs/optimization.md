# 本地任务、缓存与运维

单实例、单进程运行。下载按规范化作品 ID 合并，PDF 按完整内容身份合并。一个请求断开不会取消共享工作。每个执行类别有独立额度、有界等待和超时；队列满返回 503 / Retry-After。下载总时限包含排队、重试和退避；超时通过 DownloadControl 通知上游，真实线程退出前仍占用额度及资源身份。Python 无法强杀线程，上游若不响应取消，会一直占用相应额度；关闭宽限期结束后由容器停止时限兜底。

PDF 在独立 Python 子进程中构建；超时后 terminate，必要时 kill 并回收。唯一临时文件经父进程验证页数、加密及可读取性后原子发布。完整 PDF 与分片共享单页编码缓存，按内容摘要、质量、JPEG optimize 和编码版本索引，默认 512 MiB。文件锁防止进程间重复编码及清理正在读取的单页；单页文件超出容量时可在使用后淘汰。PDF 引擎仍为 Pillow 和 pypdf。

内部 PDF 路径位于原目录下的 `v2/<作品ID>/<内容键>.pdf`，完整和分片根目录仍可独立配置。内容键含图片清单摘要、构建版本、质量、加密和页范围。展示名继续沿用原接口的 Titletype 与质量后缀规则。`/get_pdf_path` 返回新文件的实际绝对路径。作品 ID 接受数字和大小写不敏感的 JM 前缀，前导零会被规范化；无效输入返回统一 422。

原图根目录的 `.jmapi/<作品ID>.json` 保存下载成功清单、预期页数、顺序、相对路径、大小、修改时间和 SHA-256。章节/页面顺序来自 jmcomic 下载清单。旧 `.done` 不作为完整性证据；首次请求经下载流程复用上游图片缓存并建立新清单。构建前检查缺页和损坏，必要时补下载。已验证 PDF 的热缓存只检查索引及文件属性，不扫描原图、不打开 PdfReader，原图删除后仍可读取现成 PDF；图片变化在后续原图校验/新版本构建时发现，再使旧清单的索引失效。已发出的旧 PDF 文件默认保留。

Base64 仍返回原来的 JSON 字段，按 192 KiB 原始字节分块编码。响应开始前打开文件、持有引用并计算 Content-Length；断开释放文件和额度。中途读取失败会记录日志并中止响应，客户端应按网络传输失败重试。原始 PDF 响应也持有文件引用，清理器会跳过发送中的文件。

编码和发送使用独立额度：`JMAPI_MAX_CONCURRENT_BASE64=1` 控制正在读取/编码的块，`JMAPI_MAX_CONCURRENT_BASE64_STREAMS=4` 控制已接纳的响应。每个响应最多持有一个编码块，等待客户端接收时不占编码额度。`JMAPI_RESPONSE_SEND_TIMEOUT_SECONDS=30` 限制单次 ASGI send 的阻塞时间，超时终止传输并释放资源；它不是整个文件的发送总时限。原始 PDF 同样使用该发送超时，并支持 ETag / If-Modified-Since 的 304 条件响应及既有 Range 请求。

默认使用 curl_cffi_session 复用连接，用户明确指定的传输配置优先。下载和查询客户端拥有独立 Session。应用级 JmSyncRuntime 为章节/图片提供不同线程池，避免嵌套线程池等待死锁。SIGHUP 在后台加载 option.yml，成功才切换；任务持有旧配置引用，最后一个任务退出后关闭旧 Session。失败保留当前配置。服务器 JMAPI_* 设置在启动读取，修改需重启；SIGHUP 仅重载上游配置并清空查询缓存。

下载入口、元数据和 Base64 编码另有独立、随应用关闭的线程池，大小分别跟随对应执行额度。工作线程保留 JM 任务上下文，图片请求能继承整个下载的截止时间。HTTP 超时会按剩余时限缩短；截止后停止新请求，正在工作的线程仍按原有协作取消规则占用资源，直到退出。

未显式配置时，上游 HTTP 默认连接/读取超时为 5 / 25 秒，`client.retry_times=1`。现在 retry_times 表示**一次 HTTP 调用在全部域名之间共享的重试次数**，即默认最多两次尝试；不再为每个域名重复放大预算，绝对图片 URL 也不随 API 域名数量重复请求。显式数值保留，但预算按上述新语义执行。外层作品重试仍最多三次，并共享下载总时限，等待在异步层完成。429 按 Retry-After 秒数或 HTTP 日期设置同域名冷却，下载与查询客户端共享冷却；等待期间可响应取消和截止时间。无效/缺失 Retry-After 默认等待一秒。

可在已有 option.yml 中合并以下字段；连接、Cookie、代理及用户指定的传输类型继续保留。两项超时在默认 curl_cffi 传输中合计构成单次请求总时限，最终还受操作剩余时限约束：

```yaml
client:
  retry_times: 1
  postman:
    type: curl_cffi_session
    meta_data:
      timeout: [5, 25]
```

查询支持相同参数请求合并；默认不缓存完成结果。可设置 `JMAPI_QUERY_CACHE_TTL_SECONDS=30`、`JMAPI_DETAIL_CACHE_TTL_SECONDS=300`，最多 1024 条成功结果，键含配置版本。缓存关闭时仍合并正在执行的重复查询。

下载和构建前检查目标文件系统最低剩余空间，默认 500 MiB，不足返回 503 / Retry-After，现有 PDF 继续可读。readiness 在后台线程实测原图、PDF、分片三个目录的写权限与空间，并检查关闭状态。默认只清理超过 24 小时、不属于活动任务的 `.jmapi-*.tmp`。原图和已生成 PDF 默认保留；显式开启 PDF TTL/容量回收后，旧绝对路径可能失效。回收只处理 v2 PDF，跳过引用中的文件，原版 PDF 不自动删除。

`/metrics` 使用路由模板，未知路径统一为 `__unmatched__`。请求处理耗时统计至响应头，完整响应耗时统计至发送结束，并记录断开/异常。另有活跃、等待、取消中任务、排队时间、取消次数、构建失败、磁盘拒绝和缓存命中指标。

网络补充指标为 `jmapi_upstream_requests_total{outcome}`、`jmapi_upstream_request_seconds` 和 `jmapi_response_send_timeouts_total`；不使用 URL 或域名作为动态指标标签。查询 TTL 继续默认关闭，章节/图片仍为全局 3 / 12 线程。本次没有增加多进程协调，也未改为跨作品轮转的图片调度器。

容器采用非 root UID/GID 10001，停止宽限期 40 秒，应用宽限期 30 秒。持久化 pdf、webp、pdf_cache 三个目录。Docker 发布依赖同一次提交的 Python 3.12/3.13 测试及静态检查成功，uv 固定 0.13.7。离线对比操作见 [Docker 验证](docker-comparison.md)。
